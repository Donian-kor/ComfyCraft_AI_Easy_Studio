1. 개요 · 핵심 컨셉

메인 화면을 오픈코드 같은 챗봇 형식으로 개편한다. 사용자는 자연어 대화로 이미지를 생성·수정하고, ComfyUI 세부 설정(해상도, Steps, CFG, 시드, 샘플러, 모델, FaceDetailer 등)은 별도 생성 옵션 섹션에서 그대로 조절한다.

핵심 원칙

  • 기본 상호작용은 대화로 수행한다 (오픈코드 스타일).
  • 일반 사용자는 Steps·CFG·샘플러 같은 용어를 몰라도 된다. 채팅 요구에 맞춰 모델별 최적 기본값이 자동 적용된다.
  • 이미지 생성 모델은 오픈코드처럼 입력 영역의 모델 피커에서 쉽게 선택한다.
  • ComfyUI 세부 설정은 삭제하지 않는다. 생성 옵션 섹션(기본 접힘)에 전부 유지하고, 고급 사용자가 직접 조절한다.
  • 대화 생성 시에도 현재 옵션값(스냅샷)이 그대로 워크플로우에 반영된다.
모델 역할 정의 (중요): 현 프로젝트에는 대화용 AI가 없다. 모델은 2종뿐이다 — ① 프롬프트 향상용 (LM Studio, 짧은 입력을 상세 영어 프롬프트로 변환) ② 이미지 생성용 (ComfyUI). 개편 UI의 모델 피커 = ② 이미지 생성 모델이며, 사용자와 대화하는 AI가 아니다. 채팅의 AI 응답 ("그렸어요", "수정했어요")은 어떤 모델도 생성하지 않고 앱이 상태에 맞춰 조립하는 템플릿 문장이다. "좀 더 밝게" 같은 수정 요청 해석도 LLM이 아니라 규칙 기반(마지막 생성 결과의 프롬프트 + 동일 옵션 스냅샷으로 재생성)으로 처리한다. LM 모델 선택은 생성 옵션 섹션에 유지된다.

2. 핵심 사용 흐름

단계사용자 행동시스템 반응
1. 첫 요청"이쁘고 귀여운 고양이 3마리 그려줘" 같은 자연어 입력 (옵션 용어 불필요)선택된 모델의 최적 기본값 + 프롬프트 향상(LM Studio)으로 이미지 생성
2. 결과 확인생성된 이미지 확인이미지 카드 + 모델명 + 빠른 액션. Steps·CFG 수치는 기본 노출하지 않음
3. 후속 수정"좀 더 밝게", "배경을 바꿔줘" 등 자연어 수정대화 맥락 + 동일 옵션 스냅샷으로 수정 생성
4. 모델 변경입력 영역 모델 피커에서 변경 (오픈코드식)해당 모델 최적 기본값 자동 적용 + 시스템 메시지 안내
5. 옵션 조절 (고급)생성 옵션 섹션에서 값 변경다음 생성부터 반영. "기본값으로 되돌리기" 제공
6. 저장/복사버튼 클릭 또는 "저장해줘"파일 저장, 클립보드 복사 (공유 링크 기능은 없음 — 범위 밖)

3. 설계 원칙

  • 대화 우선, 옵션 유지: 일반 사용자는 대화만으로 완결. 옵션 UI는 기본 접힘.
  • 모델별 최적 기본값 자동 적용: 모델 선택 시 최적화된 값이 자동 적용된다 (기존 ModelProfile + apply_model_defaults 재활용).
  • 오픈코드식 모델 선택: 이미지 모델은 입력 영역 피커에서 전환. LM 모델(프롬프트 향상용)은 옵션 섹션에 유지.
  • 점진적 공개: 기본 화면은 채팅+모델 피커만. 생성 옵션은 사이드바 접이식 패널.
  • 스냅샷 일관성: 전송 시점 옵션값을 build_generation_snapshot으로 고정.
  • 기존 소스 최대 재활용: 신규 위젯보다 기존 위젯·로직 이식 우선.
  • 오류 친화적: 대화 형태로 오류 설명 + 복구 옵션.
  • 접근성: 키보드 네비게이션, Qt accessibleName/accessibleDescription, WCAG 2.1 AA.

모델 변경 시 apply_model_defaults가 Steps/CFG/샘플러/스케줄러를 자동 세팅하고 채팅에 시스템 메시지로 안내. 기존 comfyModelCombo + refresh_models/set_models 로직 재활용.

6. 모델별 최적 기본값

  • app/core/model_profiles/*의 ModelProfile (family별 default_steps/default_cfg/sampler_name/scheduler, CLIP/VAE 기본값)이 최적값 저장소 — app/core/model_profiles/base.py:8-21.
  • 모델 변경 시 MainController.apply_model_defaults (app/main_controller.py:1264)가 자동 세팅. 채팅 UI에서는 시스템 메시지로 표시.
  • "귀여운 고양이 3마리" 같은 요구는 LM Studio 프롬프트 향상(enhance_prompt_sync)이 구체 프롬프트로 변환, 샘플링 설정은 모델 기본값이 담당.
  • 고급 사용자가 값을 바꾸면 스냅샷에 우선 반영. "기본값으로 되돌리기" = apply_model_defaults(현재 모델) 재호출.
  • 프롬프트 향상은 대화 전송 시 자동 수행 (LM 연결 시). 향상 결과는 채팅 AI 메시지 내 "사용된 프롬프트 ▸" 영역에서 확인·복사 가능.
  • 전송마다 독립 프롬프트 (중요): "고양이 그려줘" 다음에 "슈퍼맨 그려줘"를 보내면 슈퍼맨 프롬프트로 새로 시작한다. 이전 메시지와 합치지 않는다 ("고양이+슈퍼맨" 혼합 방지). "수정"도 새 독립 생성이며, 맥락 유지는 사용자가 주체를 반복 입력하는 방식으로 한다 ("사실적인 고양이로 바꿔줘").
  • 오래된 향상 텍스트 자동 재사용 금지: 현행 GenerationWorker는 향상 칸에 텍스트가 있으면 향상을 건너뛰고 그 텍스트를 쓴다. 채팅 구조에서는 직전 생성의 향상문이 남아 다음 메시지를 오염시킨다 ("슈퍼맨" 요청에 고양이 향상문 사용). 따라서 일반 전송 시 향상 칸을 초기화한 뒤 스냅샷을 수집한다 (P2 작업에 포함).
  • 프롬프트 재활용은 명시적 동작으로: 초기화가 재활용을 막지 않는다. 과거 메시지의 프롬프트를 쓰고 싶으면 두 경로가 있다. ① "사용된 프롬프트 ▸" 영역의 [복사] → 입력창에 붙여넣기 → 전송 (새로 향상됨). ② 이미지 카드의 [수정 요청] → 해당 메시지의 최종 프롬프트(향상문)를 입력창에 자동 로드 + "편집 중" 표시 → 고쳐서 전송 (이 경우 향상 칸으로 직행시켜 재향상 없이 사용 — 현행 스킵 로직이 정당하게 동작하는 케이스). [수정 요청]은 프롬프트만이 아니라 해당 생성의 전체 옵션 스냅샷(모델·해상도·시드·Steps·CFG·샘플러·스케줄러·ZAnime·FaceDetailer)까지 함께 복원한다 — 현행 _on_thumbnail_clicked 복원 로직(2398~2429행)을 썸네일 없이 채팅에서 재활용. 현행 메모리 generation_history(최대 4개)는 session.json 메시지로 이관하여 개수 제한 해제. 같은 프롬프트로 다른 느낌을 내려면 시드·모델·Steps를 바꿔 재생성한다.
  • ZAnime 채팅 흐름: 모델 피커에서 zanime 선택 후 전송했는데 스타일 미선택이면 생성하지 않고 AI 메시지로 "Z-Anime 스타일을 골라주세요" + 인라인 버튼 3개 (웹툰/일본애니/기본, 기존 select_zanime_style 저장 로직 재활용)를 표시한다. 버튼 클릭 시 스타일 저장 + 대기 중이던 원래 메시지로 자동 생성 시작 (프롬프트 향상→생성, 재전송 불필요). 이후 메시지는 저장된 스타일로 계속 생성된다. 현행 "스타일 선택 필요" 차단 로직 (start_generation의 ValueError 처리)을 채팅 흐름에 맞게 이식한 것이다.

8. 상태 관리 · 스타일링 · 접근성 · 오류 처리

상태 관리

  • 대화 목록 (새 대화/전환/삭제), 현재 대화 메시지. 수정 재생성 기준 = 마지막 생성 결과 1건 (프롬프트+스냅샷). LLM 대화 맥락은 사용하지 않는다 (범위 제외).
  • 생성 상태: WorkerSignals (progress/status/log/image/error/finished/enhanced_prompt) 그대로. 대기 → 생성 중 → 완료/오류/취소.
  • 옵션 스냅샷을 이미지 카드 상세 영역 + 시스템 메시지에 기록 (재현성).
  • 1회 생성 = 이미지 1장: 현행 download_first_image가 첫 번째 결과만 다운로드하므로, 이미지 카드는 1장 기준. 한 세션 안에서는 메시지마다 생성하므로 이미지 여러 장 누적 가능. 1회 요청에 여러 장(배치 생성)은 미지원 — 범위 밖.

대화 저장 형식 — session.json 도입 (확정)

4cut식 세션 저장을 도입한다. 저장 위치: 출력 디렉토리 하위 .sessions/sessions.json (중앙 인덱스) + 세션별 폴더의 session.json.

session.json
├─ session_id / title / created_at / updated_at
├─ type: "single"          ← 합병 후 4cut 만화는 "comic"으로 확장 (하위 호환)
├─ model                 ← 당시 선택 모델 (ComfyUI)
├─ messages[]            ← 채팅 복원용
│   ├─ role: user / ai / system
│   ├─ text / timestamp
│   ├─ snapshot          ← 해당 생성의 옵션 스냅샷 (build_generation_snapshot 결과)
│   ├─ image_path        ← 결과 이미지 경로 (ai 메시지)
│   └─ elapsed           ← 소요 시간 (ai 메시지)
└─ last_snapshot         ← 마지막 생성 설정 (수정 재생성·이어하기용)
  • 앱 재시작 시 마지막 세션 자동 복원. 수정 재생성은 저장된 snapshot을 그대로 재사용한다.
  • 이미지 파일 자체는 기존 출력 폴더에 유지하고, session.json에는 경로만 기록한다.
  • 저장 트리거 4종: ① 전송 시 → 세션 생성/updated_at 갱신 ② finished 시 → 메시지+snapshot+image_path+elapsed 저장 ③ 세션 전환 시 → 현 세션 저장 후 대상 로드 ④ 앱 종료 시 → 마지막 세션 저장.

범위 제외 (하지 않는 것 — 확정)

  • 로컬 LLM 실시간 채팅 연동 없음: LM Studio는 현행대로 프롬프트 향상 전용으로만 사용 (enhance_prompt_sync, 모델별 시스템 지시문). 대화 답변 생성에 LLM을 쓰지 않는다.
  • AI 응답 = 상태 템플릿: "그렸어요/수정했어요/실패했어요" 등은 앱이 조립하는 고정 문장 + 빈칸(모델명, 소요 시간, 오류 원인) 채움. 11종으로 완결 (ZAnime 스타일 선택 포함).
  • 의도 판단·자연어 명령 파싱 없음: "Steps 30으로" 같은 문장 해석, "그려줘" 의도 판별, 확인 절차 일체 미구현. 모든 입력은 이미지 프롬프트로 취급.
  • 전송 규칙 (중복 생성 방지): 전송 1회 = 생성 1회. 키워드("그려줘/만들어" 등) 유무와 무관하며, "안녕" 같은 입력도 그대로 프롬프트로 생성한다. 생성 중 잠금 범위: 텍스트 입력창·모델 피커·생성 옵션 패널은 비활성화. 단, 정지 버튼은 절대 잠그지 않는다 — 전송 버튼이 ■ 정지로 전환되어 항상 클릭 가능해야 한다 (현행 _set_ui_enabled도 generateButton만 예외로 활성 유지). 이전 결과 보기·저장도 계속 가능. 이 상태의 전송 시도는 무시하고 "생성 중이에요. 기다리거나 취소해주세요" 안내만 표시한다. 무한 호출·큐 적재는 발생하지 않는다 (start_generation의 worker 존재 가드 + _gen_pool(max_workers=1)).
  • 채택하지 않은 대안 (재제안 방지용 기록): ① 모델 피커 검색 커스텀 팝업 — 모델 5개 수준에 과잉설계이므로 QComboBox 유지. ② 수정 시 프롬프트 병합 ("이전 프롬프트+수정어 연결") — 독립 프롬프트 원칙 및 범위 제외(의도 판별 없음)와 충돌하므로 기각. ③ sidebar_frame 구 백업 참조 — 삭제된 main.ui.bak에만 존재했으므로 git 이력에서 참조. ④ 향상 단계 별도 비동기 워커 분리 — 향상은 생성 워커 스레드 내에서 실행되어 UI 블로킹이 없으므로 현행 유지.
