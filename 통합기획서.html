1. 통합 목표 · 결정 요약

4cut LocalComic Studio(v1.2.3)는 자체 채팅 UI·세션·테마·설정창을 갖고 있고, ComfyCraft는 다모델(FLUX/GGUF/ZImage/ERNIE/ZAnime) 대응 단일 이미지 생성기를 갖고 있다. 두 프로젝트의 공통 분모(ComfyUI 클라이언트, LM Studio 클라이언트, 워크플로우 어댑터, 모델 프로필, 채팅 UI, 세션 저장)는 대부분 이미 이식 완료 상태다(app/core/workflow_factory.py:3이 4cut 이식임을 명시, app/core/model_registry.py:39가 4cut식 프로필 JSON을 읽음). 남은 것은 만화 도메인 그 자체다.

결정내용근거
D1단일 프로그램 · 3모드. 하나의 채팅 UI에서 모드만 분기한다(단일 이미지 / 4컷 만화 / 8컷 웹툰). 별도 프로그램·별도 실행 파일 없음.두 저장소가 이미 한 사용자·한 ComfyUI를 공유. 분리 실행은 설정·세션·모델 관리를 중복시킨다
D2UI 기준 = ComfyCraft 유지. 3층 구조(헤더 60 / 본문 밀착 / 입력줄 58), 사이드바 5버튼(홈/옵션/이력/?/설정 · 76px), 340px 패널, 설정 3탭을 그대로 쓴다. 4cut UI 코드(chat_view_manager/sidebar/composer/empty_state/idea_section)는 이식하지 않는다.ComfyCraft에 동등물이 있고 테스트 19종 보유. 4cut UI는 v1.1~v1.2.2에서 배치 회귀 3회를 겪었다
D3엔진 계약은 "1 호출 = 1장" 유지. 만화는 상위 오케스트레이터가 이 엔진을 컷 수만큼 호출하고 마지막에 합성 1회를 추가한다. GenerationWorker 코드 변경 없음.download_first_image(generation.py:948)가 1장만 받는다. 엔진을 열면 단일 모드가 위험해진다
D4확인 게이트 신설. 만화 요청은 곧바로 GPU를 쓰지 않고 스토리 계획 확인 카드(캐릭터·스타일·컷별 장면·대사)를 띄운 뒤 [만들기]를 눌러야 시작한다.4cut은 요청 즉시 4컷 전량 생성(수 분 소요) 후 대사 확정. LLM 대사 오류를 GPU로 확인해야 하는 UX 결함
D5테마는 ComfyCraft 팔레트 유지(다크 #1a1a1a / 브랜드 #0078D4 + 라이트). 4cut의 웜그레이+코랄(#e87e60)은 채택하지 않는다. 4cut에서 가져올 것은 색이 아니라 기법 — 단일 토큰 모듈·폰트 선택기·커스텀 스크롤바.한 UI에 액센트 2개를 두면 상태색·브랜드색·선택색이 서로 경쟁한다. QSS 9벌에 만화 카드 색을 추가하는 편이 비용이 낮다
D6LM Studio는 1개 모델 · 역할 분리. 모델은 그대로 하나 두고 시스템 프롬프트만 역할별로 분리한다: enhance(프롬프트 향상, 현행) / story_plan(스토리·대사 기획, 신입) / workflow_author(워크플로우 자동 작성, 4cut 이식).4cut이 이미 같은 서버로 3가지를 처리한다. 모델을 3개로 쪼개면 설정 다이얼로그가 세 배로 불어난다
D7말풍선 감지는 선택 사항. 4cut의 YOLO/ultralytics 의존은 격리된 옵션으로 두고, 없으면 1단계(이미지)만 생성하고 대사는 이미지 위에 얹지 않는다.torch+ultralytics는 설치 크기·앱 시작 비용·크래시 위험이 모두 크다. 합성 워크플로우(stage2)도 같은 이유로 선택
D8만화는 대사 없이도 ship 가능해야 한다. I4까지(스토리 기획 + 컷 이미지 생성)가 끝나면 "대사 없는 4컷 만화"로 이미 쓸 수 있다. 대사 합성은 I5에서 뒤에 붙인다.stage2 워크플로우는 모델 계열마다 노드 구조가 달라 세팅 비용이 가장 크다
모드 정의 (확정) — ① 단일: 현행 v4.0 그대로(전송 1회 = 이미지 1장). ② 만화 4컷: 4컷 2×2. ③ 웹툰 8컷: 8컷(2장 × 4컷). 세 모드는 동일한 엔진·동일한 스냅샷·동일한 세션 스키마를 쓰고 컷 수만 다르므로 ③은 별도 페이즈가 없다.

8. 생성 일관성 정책

4cut의 ComicGenerationContext 개념을 문서 수준에서 확정한다. 만화가 시작되면 아래 값을 1회 확정하고 컷 전체에 공유한다.

ComicContext
├─ master_seed            # 마스터 시드 (사용자 변경 가능, 기본 자동)
├─ character_prompt       # LM이 만든 캐릭터 정보 + 사용자가 선택한 분위기/그림체
├─ style_prompt           # 그림체/분위기에서 파생
├─ base_snapshot          # { width, height, steps, cfg, sampler, scheduler, model, facedetailer }
└─ stage2_workflow        # "" 면 대사 미표시

컷 i의 최종 프롬프트 = character_prompt + style_prompt + scene[i]
컷 i의 시드          = master_seed + i          (1차 생성)
컷 i 재생성 시드     = master_seed + i + 1000 × revision
  • 하드코딩 금지 — 캐릭터/스타일 프롬프트를 코드에 박지 않는다. 4cut과 동일.
  • 배경 유지 — 각 컷의 배경은 scene[i]에 남은 환경 정보가 기준이다. 순백색·빈 배경으로 임의 대체하지 않는다. 단, 스토리가 흰 배경(흰 벽/눈밭)을 명시 요구하면 유지.
  • FaceDetailer는 만화에서 OFF 권장 — 컷마다 얼굴 보정 강도가 달라지면 캐릭터 일관성이 깨진다. ON 을 허용하되 경고를 표시한다.
  • 일관성 검증(선택) — 4cut은 character/style을 프롬프트로만 유지한다. 별도 임베딩/얼굴 임베딩 일관성 모델은 범위 밖.
  • 재현성 — ComicContext 전체가 세션에 저장되므로, 나중에 같은 설정을 그대로 재현할 수 있다. "이 만화 다시 만들기" = 컨텍스트를 그대로 재사용.
